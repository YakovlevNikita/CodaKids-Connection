# CodaKids Connection — Справка для агентов

## Обзор проекта

**CodaKids Connection** — веб-приложение для записи школ на мастерклассы, проводимые в июне 2026 года. Архитектура — клиентское одностраничное приложение (SPA) на чистом JavaScript с серверным PHP API и файловым хранилищем данных в формате JSON.

Основные возможности:
- Анимированный интро-экран с имитацией набора кода в редакторе и авторизацией.
- Просмотр календаря доступных дат (июнь 2026) с выбором типа мастеркласса.
- Авторизация школ и администратора через PHP-сессии.
- Запись на мастерклассы с ограничением по слотам (студийные — до 12 человек, выездные — неограниченно).
- Личный кабинет с просмотром и отменой записей.
- Админ-панель с экспортом/импортом данных в JSON, управлением записями и их полной очисткой.

Язык интерфейса, документации и комментариев в коде — **русский**.

## Технологический стек

- **HTML5** — разметка.
- **CSS3** — кастомные стили (без фреймворков), адаптивная вёрстка через `@media`.
- **Vanilla JavaScript (ES6+)** — вся логика на чистом JS, без библиотек и фреймворков.
- **PHP 7.4+** — серверное API без фреймворков (нативные сессии, работа с файлами).
- **JSON-файлы** — персистентное хранение данных (`data/users.json`, `data/workshops.json`, `data/bookings.json`).

**Нет package-менеджера, нет сборщиков, нет транспиляторов, нет конфигурационных файлов сборки** (например, `package.json`, `vite.config.js`, `composer.json`, `pyproject.toml`, `Cargo.toml` и т.п.). Нет системы управления базами данных — всё хранится в JSON-файлах на диске.

## Запуск и развёртывание

### Требования

- Веб-сервер с поддержкой PHP (Apache, nginx + php-fpm и т.п.).
- PHP 7.4 или выше с включёнными сессиями.
- Права на запись в директорию `data/` для процесса веб-сервера.

### Локальный запуск

```bash
# PHP встроенный сервер (для разработки)
php -S localhost:8000
```

### Первоначальная настройка

1. Убедитесь, что директория `data/` доступна для записи веб-серверу.
2. Пароли в `data/users.json` уже захешированы (`password_hash`). Для смены пароля используйте админ-панель.

### Деплой

Приложение **требует PHP-сервер** и не может быть развёрнуто на чисто статических хостингах (GitHub Pages, Netlify статический хостинг и т.д.). Подходящие варианты:
- Любой shared-хостинг с PHP (Beget, Reg.ru и т.п.).
- VPS/VDS с Apache/nginx + PHP.
- Облачные платформы с поддержкой PHP (Heroku, DigitalOcean App Platform и т.п.).

## Архитектура и API

### Принцип работы

1. Клиент загружает `index.html`.
2. При инициализации (`init()`, строка ~1401) фронтенд запрашивает:
   - `GET api/workshops.php` — список мастерклассов и расписание.
   - `GET api/me.php` — проверка активной PHP-сессии.
   - `GET api/bookings.php` — список записей (если авторизован).
3. Все действия (авторизация, запись, отмена, импорт) выполняются через `fetch()` к соответствующим PHP-эндпоинтам.
4. PHP использует `session_start()` для аутентификации и файловые операции для чтения/записи JSON.

### Эндпоинты API

| Метод | Эндпоинт | Описание | Доступ |
|-------|----------|----------|--------|
| POST | `api/auth.php` | Авторизация по `login` + `password`, создаёт PHP-сессию | Любой |
| GET | `api/me.php` | Возвращает текущего пользователя из сессии | Любой |
| POST | `api/logout.php` | Уничтожает сессию | Авторизованный |
| GET | `api/workshops.php` | Возвращает мастерклассы и расписание | Любой |
| GET | `api/bookings.php` | Возвращает все записи | Авторизованный |
| POST | `api/bookings.php` | Создаёт новую запись (валидация на сервере) | Авторизованный (school) |
| DELETE | `api/bookings.php` | Отменяет запись по `id` | Авторизованный |
| GET | `api/users.php` | Возвращает список пользователей (без паролей) | Только admin |
| POST | `api/users.php` | Меняет пароль пользователя (с хешированием) | Только admin |
| POST | `api/import.php` | Полная замена `bookings.json` | Только admin |
| POST | `api/settings.php` | Чтение/запись настроек блокировки направлений | Только admin |
| POST | `api/clear.php` | Очищает все записи | Только admin |

### Роли пользователей

- `school` — 19 школ (`школа1` … `школа19`), могут записываться на мастерклассы.
- `teacher` — 2 преподавателя (`yakovlev`, `semenyuk`), имеют доступ только к просмотру календарей с записями.
- `admin` — администратор, имеет доступ только к админ-панели (управление записями и пользователями), но не может записываться.

### Правила записи

- Одна школа может быть записана только на **один мастеркласс в одном слоте**.
- **Студийные** мастерклассы (`studio`) имеют лимит до 12 участников на слот.
- **Выездные** мастерклассы (`outbound`) имеют практически неограниченное число мест (`maxSlots: 999`).
- Валидация выполняется на сервере в `api/bookings.php`:
  - Проверка дублирования: если школа уже записана на этот `day` + `time`, возвращается ошибка 400.
  - Проверка лимита: для `studio` считаются существующие записи с тем же `day` + `time` + `workshopId`, если `count >= maxSlots` — ошибка 400.

### Расписание (июнь 2026)

- **Студийные (в студии)**:
  - **Фаза 1** (4, 5, 8–12 июня, рабочие дни): один слот `15:30–17:00`.
  - **Фаза 2** (15–19 июня, рабочая неделя): три слота `10:00–11:30`, `12:00–13:30`, `14:00–15:30`.
- **Выездные IT** (Яковлев Н.А.) — 17, 18, 19, 22, 23, 24, 25 июня: слоты `10:30–12:00`, `14:00–15:30`.
- **Выездные арт** (Семенюк Л.В.) — 17, 18, 19, 22, 23, 24, 25 июня: слоты `9:00–10:30`, `11:30–13:00`, `14:00–15:30`.

### Поток выбора мастеркласса

1. Пользователь видит экран с двумя карточками: «Мастерклассы в студии» и «Выездные мастерклассы».
2. При клике на «В студии» вызывается `showCalendar('studio')` — показываются даты фазы 1 и фазы 2.
3. При клике на «Выездные» открывается промежуточный экран с выбором группы: «IT-Мастерклассы» (`outbound-it`) или «Арт-тренинги» (`outbound-art`).
4. IT-выездные доступны 17–25 июня (кроме 20, 21) в слоты `10:30–12:00`, `14:00–15:30`. Арт-выездные доступны 17–25 июня (кроме 20, 21) в слоты `9:00–10:30`, `11:30–13:00`, `14:00–15:30`.
5. В календаре отображаются карточки дней со слотами. Слоты показывают статус: свободно, занято (с названием школы), или «уже есть запись» если школа записана в другой слот этого же дня.
6. При клике на свободный слот открывается `bookingModal` со списком доступных мастерклассов выбранного типа/группы.
7. При бронировании отправляется `POST api/bookings.php` с `day`, `time`, `workshopId`.

## Безопасность

> ⚠️ **Важно**: текущая реализация — демонстрационная система для внутреннего использования. Не используйте эту версию как образец для систем с реальными данными без дополнительных мер защиты.

- Пароли в `data/users.json` уже захешированы (`password_hash`). `api/auth.php` поддерживает оба формата (`password` и `password_hash`) для обратной совместимости.
- `api/utils.php` — CORS-заголовки закомментированы для продакшена. При необходимости раскомментируйте для локальной разработки.
- Нет защиты от CSRF, нет rate limiting, нет HTTPS-принудиловки.
- `api/bookings.php` проверяет роль (`school` only) при создании записи и владельца/админа при удалении.
- `api/utils.php` использует файловые блокировки (`flock`) для чтения/записи JSON.
- Фронтенд экранирует вывод через `escapeHtml()` для защиты от XSS.
- `data/.htaccess` запрещает прямой доступ к JSON-файлам (работает только на Apache).
- Админ-эндпоинты (`import.php`, `clear.php`) проверяют роль пользователя через `$_SESSION['user']['role']`.
- Валидация записей выполняется на сервере в `api/bookings.php` (проверка лимита, проверка дублирования).
- `writeJson` в `api/utils.php` использует атомарную запись через временный файл (`.tmp`) и проверяет ошибки ввода-вывода.
- `api/bookings.php` использует файл-блокировку (`.bookings.lock`) для предотвращения race condition при одновременном бронировании.

## Блокировка направлений

Администратор может временно закрыть или открыть запись на любое из трёх направлений через админ-панель (раздел «Управление записями»).

Настройки хранятся в `data/workshops.json` в поле `settings`:
```json
{
  "studioEnabled": true,
  "outboundItEnabled": false,
  "outboundArtEnabled": true
}
```

- Фронтенд проверяет флаг при клике на карточку направления (`showCalendar`) и при открытии модалки бронирования (`openBookingModal`).
- Заблокированные направления визуально выделяются (opacity 0.5, отключены клики) через `updateBookingTypeCards()`.
- API `api/settings.php` (GET/POST, только admin) управляет настройками.
- Серверная валидация в `api/bookings.php` также проверяет корректность даты/времени в зависимости от типа мастеркласса (`studio` / `outbound-it` / `outbound-art`).

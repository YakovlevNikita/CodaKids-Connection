# Деплой на Reg.ru (ISPmanager)

## Требования

- Хостинг с поддержкой PHP 7.4+ (рекомендуется 8.0+)
- Apache с включённым модулем `mod_rewrite`
- Включённые PHP-сессии
- Доступ к панели ISPmanager

## Подготовка

Проект уже подготовлен к продакшену:
- Пароли захешированы (`data/users.json` содержит `password_hash`)
- `install.php` удалён
- CORS-заголовки отключены (`api/utils.php`)
- Лишние файлы удалены (`desktop.ini`, `plan.md`, `Мастерклассы.docx`)

## Шаг 1. Загрузка файлов

### Вариант А — через FTP/SFTP
1. Подключитесь к хостингу по FTP (данные берутся из письма от Reg.ru)
2. Зайдите в корневую директорию сайта (обычно `www/имя_сайта/` или `public_html/`)
3. Загрузите **все** файлы и папки проекта:
   ```
   index.html
   .htaccess
   api/
   data/
   Teachers/
   ```

### Вариант Б — через файловый менеджер ISPmanager
1. Войдите в ISPmanager
2. Перейдите: **Главное → Файловый менеджер**
3. Откройте папку сайта (`www/имя_сайта/`)
4. Нажмите **Закачать** → выберите ZIP-архив с проектом → разархивируйте

## Шаг 2. Настройка PHP

1. В ISPmanager перейдите: **WWW → WWW-домены**
2. Кликните по вашему домену → **Изменить**
3. Установите версию PHP: **7.4** или выше (рекомендуется **8.0 / 8.1 / 8.2**)
4. Убедитесь, что включено расширение **session**
5. Сохраните

## Шаг 3. Права на папки и файлы

В файловом менеджере ISPmanager (или через SSH):

```bash
# Перейдите в корень сайта
cd ~/www/имя_сайта

# Папки
chmod 755 .
chmod 755 api
chmod 755 Teachers
chmod 755 data

# Файлы
chmod 644 index.html
chmod 644 .htaccess
chmod 644 api/*.php
chmod 644 data/.htaccess
chmod 644 Teachers/*

# JSON-файлы данных — должны быть доступны для записи
chmod 666 data/*.json
```

> **Важно:** на Reg.ru PHP обычно работает от имени вашего пользователя, поэтому достаточно `755` на папку `data/` и `644` на файлы. Если запись не работает — попробуйте `777` на папку `data/` и `666` на `*.json`.

## Шаг 4. Проверка работы

1. Откройте сайт в браузере: `https://ваш-домен.ru`
2. Проверьте авторизацию:
   - Школа: `школа1` / пароль `school1`
   - Админ: `admin` / пароль `admin123`
   - Преподаватель: `yakovlev` / `nikita123` или `semenyuk` / `larisa123`
3. Проверьте создание и отмену записи
4. Проверьте админ-панель (экспорт/импорт JSON, смена пароля)

## Шаг 5. Настройка SSL (HTTPS)

1. В ISPmanager перейдите: **WWW → WWW-домены**
2. Кликните по вашему домену → **SSL-сертификаты**
3. Установите Let's Encrypt (если ещё не установлен) → **Выпустить**
4. В настройках домена включите:
   - ✅ **Перенаправлять HTTP → HTTPS**
   - ✅ **Обработка SSL сервером**
5. Проверьте редирект: откройте `http://ваш-домен.ru` — должен автоматически перейти на `https://`

> Если редирект в панели не работает — он уже прописан в корневом `.htaccess` проекта как запасной вариант.

## Шаг 6. Безопасность (обязательно)

1. **Смените пароль администратора** сразу после первого входа (Админка → Управление пользователями)
2. Убедитесь, что `data/.htaccess` защищает JSON-файлы от прямого доступа:
   ```
   https://ваш-домен.ru/data/users.json
   ```
   Должен выдавать ошибку **403 Forbidden**.
3. Если используете Git на хостинге — убедитесь, что папка `.git/` недоступна извне (проверьте `https://ваш-домен.ru/.git/` → должно быть 403)

## Возможные проблемы

### 500 Internal Server Error
- Проверьте права на файлы (должны быть 644, на папки 755)
- Проверьте версию PHP (минимум 7.4)
- Проверьте наличие `mod_rewrite` (включается в настройках домена ISPmanager)

### Не работает авторизация / сессии
- В настройках PHP домена включите расширение **session**
- Проверьте, что в `php.ini` параметр `session.save_path` указывает на доступную для записи папку

### Не сохраняются записи (bookings.json)
- Установите права `777` на папку `data/` и `666` на файлы `*.json` внутри неё
- Проверьте, что PHP работает от имени пользователя (а не apache/www-data)

### CORS-ошибки в консоли браузера
- Если фронтенд и API на одном домене — CORS не нужен
- Если используете поддомен для API — раскомментируйте CORS-заголовки в `api/utils.php`
